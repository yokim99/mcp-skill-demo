MCP 与 Skill 的区别

一个解决“能连什么”，一个解决“怎么做”

MCP

Model Context Protocol
一套开放标准协议，让 AI 连接外部工具与数据源
  • 像“USB 接口”，插上就能调用数据库、API、文件系统
  • 客户端—服务器架构，运行时按需调用
  • 解决“AI 够不够得着外部世界”

Skill

能力包 / 技能
一份能力包，用指令与脚本告诉 AI 特定任务该怎么做
  • 像“操作手册”，照着就能把活干对
  • 通常是文件（SKILL.md + 脚本资源），零依赖
  • 解决“AI 做得对不对、像不像专家”

六个维度，看清差异

MCP 是“通道”，Skill 是“经验”——两者维度不同
对比维度MCPSkill
本质通信协议 / 接口标准指令 + 资源的能力包
解决的问题能不能访问外部系统如何高质量完成特定任务
形态客户端—服务器，需运行服务纯文件（SKILL.md + 脚本）
生效时机运行时动态调用工具加载进上下文，指导行为
依赖需连接服务、鉴权通常零依赖，拷文件即可
一句话类比USB 接口：插上就能用操作手册：照着就能干好

不是二选一，而是相互配合

MCP 给“手脚”，Skill 给“大脑”——组合起来才是专家
① Skill 决策

决定“这活怎么干”：评审规则、步骤、话术

→
② MCP 取数

把代码 / 数据 / 接口取回到 AI 面前

→
③ 输出结果

既有“料”又有“法”，给出专业交付

例子：一次“代码评审”
评审 Skill 提供“怎么评”的标准与方法 → MCP 通过 Git 工具把代码拉回来 → AI 按标准给出评审意见。
一句话：MCP 解决“连得上”，Skill 解决“用得好”。
